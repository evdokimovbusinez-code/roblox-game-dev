# Работа в Studio через встроенный MCP-сервер и Assistant (агент внутри открытого плейса)

**Назначение.** Файл объясняет, как ИИ-агент (Claude Code, Cursor, Codex CLI, Gemini CLI, VS Code и др.) работает внутри Roblox Studio через встроенный MCP-сервер и как использовать Assistant: подключение, список инструментов (и почему его нельзя хардкодить), режимы Edit/Client/Server, цикл «исследовать → изменить → проиграть → проверить», скриншоты и симуляция ввода, генерация ассетов и квоты, разделение труда между Script Sync/Rojo, MCP и CI, а также правила безопасности для агента, который правит живой плейс. Файловая сторона (Rojo, Open Cloud, CI) — `builder/project-setup.md`; код и архитектура — `builder/code-architecture.md`; весь процесс по стадиям — `builder/pipeline.md`; арт и UI — `builder/art-ui-audio.md`.

**Актуально на:** октябрь 2026.
**Перепроверять:**
- список и имена инструментов MCP (дрейфуют каждые несколько месяцев — всегда `tools/list`);
- обязательность `studio_id` в каждом вызове (с 19–21.08.2026; `set_active_studio` удалён);
- статус Script Sync (beta или GA; страница без beta с 24.06.2026);
- квоты Assistant (суточный лимит существует, число нигде не опубликовано) и генерации меша/материала (не опубликованы);
- известные проблемы (редактирование Edit-DataModel во время Play, сбои Start/Stop, падения при длинных сессиях);
- BYOK и условия подписки/оплаты моделей;
- Roblox Build (мобильный AI-создатель) — статус и кредиты.

## 0. Главные правила (TL;DR)

1. **Всегда вызывайте `tools/list`.** Имена инструментов менялись как минимум дважды за 2026 год (апрель → июль → август); хардкод ломается. Никакие имена из этого файла не считать контрактом.
2. **В каждом вызове нужен `studio_id`** (с 21.08.2026 документации; `set_active_studio` удалён 19.08.2026). Получить его и Place ID — `list_roblox_studios`.
3. **MCP-клиент может читать и менять любой открытый плейс, включая запуск произвольного Luau.** Подключать только доверенные клиенты; откат — Git и Place Version History.
4. **Агент работает в TEST-копии, не в PROD.** Если в Studio включён доступ к API Services, плейтест может писать в настоящие DataStore вселенной; боевую вселенную агенту не открывать.
5. **Код — файлами (Rojo/Script Sync + Git), мир и всё, чего нет в файлах — через MCP.** MCP закрывает то, что Script Sync не умеет (StarterGui, StarterPack, визуальная проверка, плейтест).
6. **Каждое изменение проверяется плейтестом:** `start_stop_play` → `get_console_output` → `screen_capture`. Не «должно работать», а «проиграно и увидено».
7. **Публикация, настройки Dashboard, пассы/продукты, анкета — не через MCP.** Это CI/Open Cloud и люди (`project-setup.md`). У Roblox «нет планов» на создание developer products через MCP.
8. **Assistant — ограниченный по суточной квоте ресурс.** Для тяжёлой агентской работы используйте внешнего агента через MCP (платите своему провайдеру модели) либо BYOK; встроенный Assistant держите для Roblox-специфичных навыков (`rbx-*`).
9. **Коммит перед сессией и после каждой проверенной фазы.** Долгие сессии иногда падают; «строить игру по одной протестированной фазе за раз» — рецепт самой Roblox.
10. **Генерация ассетов — как черновик:** лимиты на треугольники (меш ≤20 000), модерация и квоты; результат проверяется скриншотом и профайлером, а не верой.

## 1. Что есть: MCP-сервер, Assistant, навыки, Studio CLI

**Встроенный Studio MCP-сервер.** Работает локально по stdio внутри Studio. Внешние инструменты исследуют DataModel, пишут скрипты, исполняют Luau, запускают и останавливают плейтест, симулируют ввод и генерируют ассеты. Дата выхода встроенного сервера как «рекомендованного способа подключения внешних ИИ-инструментов» — 05.03.2026 (DevForum). Open-source `Roblox/studio-rust-mcp-server` (последний коммит 03.04.2026, v0.2.365) теперь в README: «no longer being actively developed» — рекомендован встроенный; новые проекты на нём не строить.

**Хронология (по датированным постам DevForum и истории документации):**

| Дата | Событие |
|---|---|
| 05.03.2026 | Встроенный MCP: `list_roblox_studios`, `set_active_studio`, `start_stop_play`, `get_console_output`, `user_mouse_input`, `user_keyboard_input`, `character_navigation` |
| 19.03.2026 | `generate_mesh` (по умолчанию до 10 000 треугольников), `generate_material`, вставка из Creator Store, `screen_capture` (JPEG, чтобы укладываться в ~1 MB результата инструмента у клиентов вроде Claude) |
| 16.04.2026 | В документации 18 инструментов (`insert_from_creator_store`, `console_output`, `playtest_subagent`, `keyboard_input`, `mouse_input`, `set_active_studio` …) |
| 17.04.2026 | Assistant: Planning Mode |
| 07.07.2026 | 27 инструментов; переименования (`get_console_output`, `user_keyboard_input`, `user_mouse_input`, `subagent` с типами `explore`/`playtest`, `search_asset` + `insert_asset`); новые: `generate_procedural_model`, `wait_job_finished`, `upload_image`, `store_image`, `get_studio_state`, `screen_capture`, `http_get`, `skill` |
| 19.08.2026 | **Breaking:** `set_active_studio` удалён; каждый вызов принимает `studio_id`; список подключённых клиентов — в настройках Assistant |

Имена `run_script_in_play_mode` и `get_studio_mode` из февральской прессы в документации никогда не появлялись — считать доимённой стадией. Третьи источники (MoguraVR, creation.dev) датируют «расширенный MCP и внешние LLM» февралём 2026; датированные посты DevForum считаются более надёжными.

**Assistant (встроенный).** Чат на каждое место (без жёсткого лимита числа чатов), у каждого чата свой контекст. Planning Mode (`/plan`): облачные приватные редактируемые Markdown-планы, исполняются **только** по команде Build, сами не запускаются. Субагенты: поиск по DataModel, playtest, screen-capture. BYOK: ключи Anthropic, OpenAI, Google (Manage API Keys, выпадающий список моделей). Команды генерации: `/generate_mesh` (текст или изображение; выделенный Part может служить bounding box), `/generate_procedural_model` (**50 за скользящие 24 часа**), `/segment_mesh` (до 8 частей на сгенерированную модель; импортированные меши — по 5 за раз). Квота сообщений и цена не документированы; на форуме подтверждён суточный лимит, «быстро исчерпываемый в обычной работе» (запрос 4686944, 17.06.2026), без ответа сотрудников; сообщения «сбрасывается за 5 дней», «пропуск стоит 500 Robux» не подтверждены — не использовать. Неудачные/зависшие генерации, по сообщениям, тоже тратят лимит.

**Навыки (skills).** Markdown-файл с frontmatter `name` / `description` / `enabled`; подключаются автоматически по описанию либо вручную через `/`; привязаны к аккаунту и работают во всех плейсах. Префикс `rbx-` зарезервирован за Roblox:
- `rbx-create-skill`, `rbx-debug` (брейкпоинты, стеки вызовов, локальные переменные), `rbx-device-simulator-lua`, `rbx-docs-search`, `rbx-perf-profiling` (разбор трасс MicroProfiler), `rbx-scene-analysis` (SceneAnalysisService: память, утечки неприкреплённых инстансов, состав треугольников), `rbx-unit-test` (определяет Jest-Lua/TestEZ, есть запасной прогон).
Дублирование Roblox-навыка отключает оригинал, копия не получает обновлений. Инструмент MCP `skill` отдаёт те же знания внешним агентам — внешний агент должен вызывать их, а не придумывать API.

**Studio CLI** (полезен для CI и агентов): `RobloxStudio --task RunScript --placeId P --universeId U --runScriptFile smoke.luau --outputFile out.log --quitAfterExecution` (скрипт с правами командной строки после загрузки места, можно `--localPlaceFile`); `--task EditPlace|EditPlaceRevision|EditFile|TryAsset`, `--openScriptPath`; `--api`, `--fullApi`, `--apiV2 <path>` выгружают API в JSON (для определений luau-lsp и «приземления» агента). Verbose-логи Studio идут в stdout.

**Roblox Build** — отдельный мобильный AI-создатель простых 2D/2.5D игр (страница от 11.06.2026): публикация в одно касание, ежедневные бесплатные подсказки, дальше кредиты за Robux. Экспорта кода нет → не производственный путь для нашего пайплайна, но конкурент для тривиальных форматов (клики, простая аркада).

Источники: create.roblox.com/docs/studio/mcp; .../assistant/guide, .../assistant/mcp, .../assistant/skills; .../ai/coding-harness, .../ai/build; .../studio/cli; DevForum: Assistant Updates (built-in MCP, 05.03.2026), Mesh Generation and new MCP tools (19.03.2026), Studio MCP Multi-Agent Improvements (19.08.2026).

## 2. Подключение и настройка

1. В Studio: Assistant → «⋯» → Manage MCP Servers → **Enable Studio as MCP server**. Зелёный индикатор показывает число подключённых клиентов.
2. **Quick Connect** в один шаг: Antigravity, Codex CLI, Claude Code, Claude Desktop, Cursor, Gemini CLI, VS Code. Для любого другого stdio-клиента — JSON-конфиг: на macOS `"command": "/Applications/RobloxStudio.app/Contents/MacOS/StudioMCP"`; на Windows `cmd.exe /c %LOCALAPPDATA%\Roblox\mcp.bat`.
3. Studio должна быть **запущена и залогинена на рабочем компьютере**. Чисто облачный агент без доступа к машине пользователя MCP использовать не может; в CI роль Studio играет Luau Execution (`project-setup.md`, §9).
4. Рецепт Roblox «Build with a coding harness» (28.07.2026): VS Code + расширение Claude Code (или Cursor) + Git → стартовый репозиторий (WaveSurvival: `ServerScriptService/`, `ReplicatedStorage/`, `StarterPlayerScripts/`, `.gitignore` с `.rbxlx`) → File → Save to File как `.rbxlx` внутри репозитория → включить **Script Sync** → правый клик по сервису → Script Sync → Sync to → *верхнеуровневая* папка репозитория (папки сопоставляются по именам) → включить MCP и Quick Connect → проверить `game:GetService("InstanceFileSyncService"):GetStatus(instance)` → закоммитить → вести проект по файлу спецификации (`WAVE_SURVIVAL.md`) «по одной проверенной фазе». Script Sync в этом туториале назван beta (File → Beta Features), а основная страница `scripting/sync` без beta с 24.06.2026: если пункт есть в Beta Features — включите, иначе он уже включён.
5. Для нашего проекта вместо Script Sync по умолчанию Rojo (`assets/template/`): `rojo serve` + плагин, MCP — поверх. Script Sync не синхронизирует атрибуты и теги, до 10 000 скриптов на корень и 128 корней, работает с Team Create (сторонние инструменты часто нет).
6. Секреты и ключи Open Cloud в MCP-сессию не передаются — агент не должен их видеть (`project-setup.md`, §5).

## 3. Инструменты MCP и режимы

Сгруппированный список на 21.08.2026 (**сверяйте с `tools/list`**; параметры — по схеме инструмента):

| Группа | Инструменты | Заметки |
|---|---|---|
| Скрипты | `script_read`, `multi_edit`, `script_search` (≤10 результатов), `script_grep` (≤50 совпадений) | Читать можно всегда; при Rojo/Script Sync править файлы, а не скрипты через MCP, иначе будет двойная правда |
| Генерация | `generate_mesh`, `generate_material`, `generate_procedural_model`, `wait_job_finished` | Генерация асинхронна: дождаться задачи |
| Ассеты | `search_asset`, `insert_asset`, `upload_image`, `store_image` | Creator Store — проверять скрипты внутри (`project-setup.md`, §8) |
| Дерево данных | `search_game_tree`, `inspect_instance`, `subagent` (типы `explore`, `playtest`) | Дешёвая разведка вместо ручного обхода |
| Исполнение | `execute_luau` | `datamodel_type`: **Edit / Client / Server** |
| Плейтест | `start_stop_play`, `get_studio_state`, `get_console_output`, `screen_capture` (необязательная позиция камеры) | Цикл проверки (§4) |
| Ввод | `character_navigation`, `user_keyboard_input`, `user_mouse_input` | Симуляция игрока |
| Документация | `http_get`, `skill` | `skill` отдаёт `rbx-*` знания |
| Сессии | `list_roblox_studios` | Возвращает `studio_id` и Place ID |

**Режимы DataModel.** `execute_luau` выбирает среду выполнения: **Edit** — рабочее дерево редактора (создание Parts, генерация мира, терраин); **Server** и **Client** — во время плейтеста, когда запущены сервер и клиент (проверка серверной логики, чтение состояния клиента, вызов remote от лица клиента). Известная проблема: инструменты, работающие с Edit-DataModel, **не работают во время Play** — сначала остановите плейтест (§10).

**Права и пределы.** Скрипт из `execute_luau` — это не обычный игровой скрипт: он может менять или удалять что угодно в открытом месте. Поэтому правила §8. `http_get` — для документации, не для обхода песочницы игры. Для данных MicroProfiler: `debug.profilebegin/profileend` работают и через MCP, сохранение — HTML.

**Многоагентность.** С 08.2026 несколько внешних клиентов могут быть подключены одновременно, список виден в настройках Assistant; каждый вызов адресуется по `studio_id` — разные агенты работают с разными окнами Studio. Не направляйте двух агентов на один плейс.

## 4. Цикл работы агента: исследовать, изменить, проиграть, проверить

**Цикл для каждой фазы (одна фича — одна фаза):**
1. **Спецификация фазы** из `SPEC.md` (§9): что должно быть видно и работать, критерии приёмки.
2. **Разведка:** `subagent(explore)` / `search_game_tree` / `inspect_instance` / `script_grep` — что уже есть; не создавать дубликаты.
3. **План** (Planning Mode или текстовый список в ответе): файлы, instance'ы, remotes, риски. Крупные изменения — после согласования с человеком.
4. **Изменение:** код — в файлы (Rojo/Script Sync), мир — генератором на Luau через `execute_luau` (Edit), не вручную перетаскиванием.
5. **Проверка кода статически:** `selene`, `stylua --check`, `luau-lsp analyze` (быстро, до Studio).
6. **Плейтест:** `start_stop_play` (запуск) → `character_navigation` / `user_*_input` для сценария → `get_console_output` (ошибки, warn'ы, собственные `print`-маркеры) → `screen_capture` (визуальная проверка) → `start_stop_play` (остановка).
7. **Исправление или фиксация:** если консоль красная — вернуться к шагу 4; если зелёная и скриншот соответствует критериям — коммит.
8. **Отчёт человеку:** что сделано, что проверено (какие сценарии, какие скриншоты), что не проверено.

**Цикл построения мира.** (1) Хранить в репозитории детерминированный Luau-модуль генерации (Parts, Terrain), (2) запускать его в Edit через `execute_luau`, (3) `screen_capture` с нескольких позиций камеры, (4) самокритика по списку (читаемость силуэтов, пустоты, масштаб персонажа относительно проёмов, освещение), (5) итерация, (6) смоук-плейтест, (7) фиксация мира в `world/*.rbxm` (`rojo syncback --input place.rbxl` либо экспорт из Studio). Генератор на Luau делает мир воспроизводимым и читаемым в диффах, даже если результат бинарный.

**Playtest-субагент.** `subagent` с типом `playtest` проходит сценарий сам (запуск, ввод, наблюдение). Использовать для регрессии «основной цикл до первой награды»; детали сценариев писать в `SPEC.md`. Мультиклиентные тесты (сервер + до 8 клиентов) скриптуются через `StudioTestService:ExecuteMultiplayerTestAsync`, а не через `start_stop_play`; `VirtualInput` и `StudioDeviceSimulatorService` — для ввода и проверки устройств (`code-architecture.md`, §9).

**Что считается проверкой.** Для фичи с UI — скриншоты минимум в трёх разрешениях и портретной/ландшафтной ориентации телефона; для серверной логики — лог с ожидаемыми маркерами; для экономики — скрипт-симуляция на `execute_luau` или Jest в CI; для производительности — MicroProfiler/Scene Analysis (`rbx-perf-profiling`, `rbx-scene-analysis`) и в конце проверка на настоящем слабом Android (Studio искажает статистику, эмулятор неточен по памяти).

## 5. Скриншоты и симуляция ввода: что и как проверять

- `screen_capture` возвращает JPEG (укладывается в ограничения размера результата у клиентов); можно задать позицию камеры, чтобы осмотреть сцену с нескольких точек. Для UI — проверка в режиме плейтеста, где отрисован PlayerGui.
- **Чек-лист UI-скриншота:** безопасные зоны (`ScreenGui.ScreenInsets = CoreUISafeInsets` по умолчанию, не перекрывать верхнюю панель и вырезы), читаемость текста на самом маленьком экране, масштаб (Scale для макета, Offset — для границ/отступов; `UIAspectRatioConstraint` перекрывает layout), касательные цели не меньше пальца, нет наложений с системным чатом и списком игроков. Подробности — `builder/art-ui-audio.md`.
- **Ввод:** `character_navigation` — перемещение персонажа к точке; `user_keyboard_input`/`user_mouse_input` — нажатия и клики. Для игр на IAS убедитесь, что у каждого действия есть привязка для касаний (`UIButton`), иначе мобильный сценарий не воспроизвести.
- **Ограничения:** симуляция ввода не заменяет проверку на реальном телефоне (жесты, тач-зоны, задержка); скриншоты Studio не показывают реальную нагрузку GPU на слабых устройствах.
- Для хоррор-игр дополнительно проверять: видимость в тёмных сценах при минимальной яркости, читаемость подсказок, отсутствие «пустых» кадров на загрузке (`ReplicatedFirst`), работу `StreamingEnabled` (Atomic для ключевых моделей).

<a id="6"></a>
## 6. Генерация ассетов и квоты

| Что | Как | Лимиты и заметки |
|---|---|---|
| Меш | `generate_mesh` (текст/изображение) | По умолчанию до 10 000 треугольников; общий лимит меша ≤20 000; квота **не опубликована** |
| Материал | `generate_material` → MaterialVariant | Квота не опубликована; Material Generator в Studio делает материал из текста |
| Текстура меша | Texture Generator (Model → Texture): Fast (1K diffuse) / Quality (4K PBR) | Работает на выделенном меше или модели; фоновая задача; квоты не найдены |
| Процедурная модель | `generate_procedural_model` | **50 за скользящие 24 часа** |
| Runtime | `GenerationService:GenerateModelAsync(inputs, schema)` | Схемы `Car5`, `Body1`; bounding box и максимум треугольников |
| Creator Store | `search_asset` + `insert_asset` | Следить за скриптами в ассете (`getfenv`, `loadstring`, `require(assetId)`, обфускация — ограничены стором); безопаснее безскриптовые меши и верифицированные авторы |
| Свои файлы | `upload_image` / `store_image`, Open Cloud Assets API, Asphalt, Roblox Blender plugin (open-source, Open Cloud, v1.0.5) | Квоты аудио 2 000/100 за 30 дней; видео стоит 2 000 Robux |

«Cube» — название генеративной 3D-модели Roblox; Assistant, MCP и GenerationService — поверхности к ней. Правила: (1) сгенерированное — черновик: проверить масштаб, силуэт, треугольники, коллизии (`CollisionFidelity` Box/Hull вместо `PreciseConvexDecomposition` для мелочей), (2) ассеты в состоянии модерации Reviewing невидимы игрокам при публикации, (3) генерация расходует суточные квоты — не гонять циклом, (4) арт-стиль единый — прокладывать через `builder/art-ui-audio.md` (палитры, правила силуэта), (5) стоимость геймплея: числа треугольников и draw calls (пример бюджета документации: <1 000 draw calls, <1 000 000 треугольников на базовом устройстве).

<a id="7"></a>
## 7. Разделение труда: Script Sync / Rojo, MCP, CI

| Задача | Чем делать | Почему |
|---|---|---|
| Серверный/клиентский код, ModuleScript, `.model.json` remotes | **Файлы** (Rojo или Script Sync) + Git | Диффы, ревью, откат, CI |
| StarterGui, StarterPack, объекты, которых нет в файлах | **MCP** (`execute_luau` в Edit, `insert_asset`) | Script Sync/Rojo их не покрывают в этом рецепте |
| Мир (Parts, Terrain) | Генератор Luau через MCP → `world/*.rbxm` | Воспроизводимость; бинарники — `.rbxm` |
| Unions, SurfaceAppearance, Editable*, BaseWrap | Studio (человек или MCP) + **публикация из Studio** | Place Publishing API их не обновляет |
| Проверка визуала, мобильный UI, плейтест | **MCP** (`screen_capture`, `start_stop_play`, ввод) | Только Studio видит клиентский рендер |
| Линт, формат, типы, Jest, облачные тесты | **CI** | Быстро, без Studio, воспроизводимо |
| Публикация версии, рестарт серверов, Configs, Experiments | **CI / Open Cloud** | Нужны ключи; агент в Studio их не видит |
| Passes, Developer Products, Badges, иконка, thumbnails | **Open Cloud** (`project-setup.md`, §7) | Нет планов добавлять продукты в MCP |
| Анкета, релиз, жанр, DevEx, уведомления | **Человек** | Только Dashboard/UI |

Правило «одна правда»: скрипт либо в файле (синхронизируется), либо только в Studio — не оба; иначе Rojo/Script Sync перезапишут правку. При Script Sync/Rojo через MCP читать скрипты можно, править — через файлы.

<a id="8"></a>
## 8. Правила безопасности для агента в живом плейсе

1. **TEST, не PROD.** Агентские сессии идут в тестовой вселенной/копии. В PROD-вселенной плейтест при включённом «Enable Studio Access to API Services» способен менять реальные DataStore; ProfileStore проверяет доступ при старте (`ProfileStore.DataStoreState`: `Access`/`NoAccess`/`NoInternet`) и при отсутствии доступа пишет «data will not be saved». Не включайте доступ к API Services в агентской сессии без необходимости, а если включили — только во вселенной TEST.
2. **Откат прежде изменений.** До сессии: чистый `git status`, коммит; в Studio — Place Version History (по вторичному источнику, переработана в 02.2026) для сравнения и восстановления. MCP-клиенты рассматривайте как имеющие полный write-доступ.
3. **Список запрещённого без явного согласия человека:** публикация места, изменение настроек Dashboard, вызовы платёжных/покупных API с реальными Robux, массовое удаление (`Destroy` корневых контейнеров, очистка Workspace), запись в DataStore/MemoryStore боевой вселенной, отправка пользовательских данных наружу через `HttpService`, включение `LoadStringEnabled` вне тестового плейса.
4. **Минимальный охват `execute_luau`:** скрипты, которые пишут в дерево, начинаются с описания, что именно меняют; удаляющие операции ограничены конкретным родителем; результат проверяется `inspect_instance`.
5. **Секреты не попадают в плейс и не печатаются в консоль:** ключи Open Cloud — только в Secrets store игры или CI; в MCP-сессию их не передаём.
6. **Сторонние ассеты:** вставка из Creator Store — только после проверки скриптов; бэкдоры из Toolbox — известная угроза; при необходимости `Sandboxed`/`Capabilities` (`code-architecture.md`, §5).
7. **Team Create:** агенту не править плейс, в котором одновременно работает человек, без договорённости (Live Scripting убирает блокировки, но конфликтов правок не исключает); для Team Create нужны возрастные проверки соавторов.
8. **Один агент на один плейс.** Несколько клиентов допустимы, но действовать должен один.
9. **Контентная ответственность:** AI-сгенерированный контент модерируется как любой другой; анкета рейтинга должна отражать самый экстремальный контент, включая сгенерированный (`builder/compliance.md`).
10. **Честный отчёт:** что агент проверил сам, что не проверял; ошибки и сбои Studio — в отчёте, не молча.

## 9. Протокол сессии и шаблон спецификации

**Старт сессии (чек-лист агента):**
1. `tools/list` → сохранить фактические имена; `list_roblox_studios` → `studio_id` и Place ID; убедиться, что это TEST.
2. `get_studio_state`; открыть `SPEC.md` и `release/HUMAN_STEPS.md`; проверить `git status`.
3. Убедиться, что Rojo/Script Sync подключены (`InstanceFileSyncService:GetStatus` либо индикатор Rojo-плагина).
4. Выбрать одну фазу; написать план; согласовать, если фаза меняет данные игрока или монетизацию.
5. Работать по циклу §4; коммит после каждой проверенной фазы; в конце — отчёт.

**Шаблон `SPEC.md` для агента** (держите в корне репозитория):
```
# <Игра> — спецификация
Цель одной строкой. Жанр и ядро цикла (30 секунд). Платформы (мобильный приоритет).
## Фазы (по одной проверенной за раз)
1. Каркас: шаблон assets/template, подключены Rojo + MCP, пустой мир, HUD — приёмка: плейтест без ошибок
2. Ядро цикла: <что делает игрок, награда за ~30 секунд> — приёмка: сценарий X за N шагов, скриншоты A/B
3. Прогрессия и экономика: валюты, цены в Config/Configs, аналитика-события
4. Монетизация: продукты/пассы (создаёт CI), PolicyService-гейты
5. Контент и полировка: UI, звук, эффекты (juice), онбординг
## Критерии приёмки (общие)
Нет ошибок в консоли; strict-анализ чист; мобильный UI читаем; сохранение и повторный вход работают.
## Ограничения
Не менять: ... Нельзя: ... Бюджеты: треугольники, draw calls, память.
```

<a id="10"></a>
## 10. Рецепты (готовые последовательности для типовых задач)

**R1. Первый запуск шаблона (смоук).** `tools/list` → `list_roblox_studios` → убедиться, что открыт TEST → Rojo подключён (`rojo serve`) → `start_stop_play` → `get_console_output`: ожидаем отсутствие ошибок и строки ProfileStore о доступе к API; `screen_capture`: HUD с монетами в правом верхнем углу → `start_stop_play` (стоп). Если ProfileStore пишет «data will not be saved» — включён режим без Studio-доступа к API, сохранение проверять нельзя (это нормально для первого смоука).

**R2. Проверка сохранения и миграций.** Только в TEST-вселенной с включённым «Enable Studio Access to API Services»: playtest → `execute_luau` (Server): изменить `Coins` через сервис (не прямой записью в DataStore) → выйти из плейтеста (сессия завершается и сохраняется) → снова playtest → убедиться, что значение вернулось. Миграции: подготовить старый формат в тестовом ключе, поднять `SCHEMA_VERSION`, зайти, убедиться по логам, что миграция прошла до `Reconcile`. Логику миграций дополнительно покрыть Jest в CI.

**R3. Серверная валидация remote.** `execute_luau` (Client): вызвать `FireServer` с мусором (`NaN`, `math.huge`, строка невалидного UTF-8, неизвестный ключ, 1000 вызовов подряд) → `get_console_output` (Server): нет ошибок и нет изменения состояния, rate limit отсёк избыток. Это проверка собственного кода, не обход чужих систем.

**R4. Мобильный UI-свип.** `StudioDeviceSimulatorService` (или эмулятор устройств Studio) + `screen_capture` на 3–4 профиля (маленький телефон, обычный телефон, планшет, ландшафт). Критерии: нет перекрытия верхней панели и вырезов, текст читается, кнопки достижимы большим пальцем. Итог — таблица «профиль → замечания» и правки; финальная проверка на реальном устройстве за человеком.

**R5. Диагностика производительности.** Навык `rbx-perf-profiling` (или MicroProfiler: Ctrl+Alt+F6, метки `debug.profilebegin`) + `rbx-scene-analysis` (память, утечки неприкреплённых инстансов, состав треугольников). Смотреть: `GraphicsMeshParts`/`GraphicsTexture`/`Sounds`, `updateInvalidatedFastClusters` >4 мс, число Humanoid/NPC, «Print Join Size Breakdown» для времени входа. Сравнить с порогами (`code-architecture.md`, §7). Решение — оптимизация, а не отключение проверок.

**R6. Воспроизведение бага.** `subagent(playtest)` либо `character_navigation` + ввод до места сбоя → `get_console_output` (стек) → гипотеза → правка файлом → тот же сценарий ещё раз → зелёный лог + скриншот → коммит с описанием воспроизведения. Баг без повторного прогона не считается исправленным.

**R7. Детерминированный генератор мира (Edit).** Шаблон: идемпотентный модуль, который сам чистит свою папку и строит заново.
```luau
--!strict
-- world/Generator.luau — запускается через execute_luau (Edit) или в Luau Execution; безопасно запускать много раз
local Generator = {}
local FOLDER = "Generated"

function Generator.build(seed: number)
	local old = workspace:FindFirstChild(FOLDER)
	if old then old:Destroy() end -- удаляем только СВОЮ папку
	local root = Instance.new("Folder")
	root.Name = FOLDER
	local rng = Random.new(seed)
	for i = 1, 40 do
		local part = Instance.new("Part")
		part.Anchored = true
		part.Size = Vector3.new(rng:NextInteger(6, 14), rng:NextInteger(8, 20), rng:NextInteger(6, 14))
		part.Position = Vector3.new(rng:NextInteger(-200, 200), part.Size.Y / 2, rng:NextInteger(-200, 200))
		part.Parent = root -- сначала свойства, потом Parent
	end
	root.Parent = workspace
end

return Generator
```
Правила генератора: seed хранится в репозитории; удаляется только собственная папка; анкеровка и коллизии заданы явно; результат не содержит union/SurfaceAppearance (их не обновит API-публикация); после удачной генерации — `world/*.rbxm`.

**R8. Откат.** Плохое изменение в файлах — `git restore`/`git revert` (Rojo/Script Sync подтянут). Плохое изменение мира — вернуть `world/*.rbxm` из Git и пересобрать, либо Place Version History в Studio. Не откатывать «вручную тем же агентом» без сверки с Git.

**Типовые ошибки агента (и контрмеры).** (1) Хардкод имён инструментов — читать `tools/list`. (2) Правка скрипта через MCP при активном Rojo — потеря правки; править файл. (3) «Починил, не проверил» — обязательный плейтест и лог. (4) Генерация мира без seed — невоспроизводимо. (5) Запуск `execute_luau` с `Destroy()` по корню — запрещено §8. (6) Игнорирование Server/Client-режима — клиентская проверка серверной логики ничего не доказывает. (7) Оптимизация по Studio-цифрам — Studio искажает статистику.

## 11. Известные проблемы и обходные пути

| Проблема | Обход |
|---|---|
| Инструменты Edit-DataModel не работают, пока идёт Play | Остановить плейтест, затем править; править файлами, а не через MCP |
| Start/Stop плейтеста у Claude иногда не срабатывает до перезапуска Studio | Перезапустить Studio, переподключить клиент, взять новый `studio_id` |
| Падения Studio в длинных сессиях | Коммит после каждой фазы; короткие сессии; Place Version History |
| Дрейф имён инструментов | `tools/list` в начале сессии |
| Старые `globalTypes` не знают новых API (например, `BindReceiptHandler`) | Свежие определения в CI; `:: any` с комментарием |
| Лимит Assistant исчерпан | Переход на внешний агент через MCP или BYOK |
| Генерация зависла/упала и списала лимит | Не повторять циклом; выждать; использовать готовые ассеты |
| Результат инструмента слишком большой (скриншот) | JPEG-режим по умолчанию; делать несколько кадров меньшего размера |
